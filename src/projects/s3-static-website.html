S3 Static Website Hosting

Started: October 2026 · Bootcamp: AWS Solutions Architect
Business Requirement

I'm moving into cloud engineering and need a public portfolio that recruiters can open on any device. It must run on my own domain over HTTPS, have no servers to patch, keep its storage bucket private and cost very little.

How would you host a portfolio website like this?

Static hosting on an Amazon S3 bucket instead of a server

Problems I Hit and How I Fixed Them

Problem 1

The site broke when I made the bucket private
Trying to: make the S3 bucket private so only CloudFront can read it.
What happened: after I turned on S3 Block Public Access, https://appcomplish.click returned an S3 AccessDenied error, although the HTTP to HTTPS redirect still worked.
Why: the origin's Origin access setting was still Public, so CloudFront sent unsigned requests, which a private bucket refuses.

Fix
  1. In CloudFront → my distribution → Origins → Edit the S3 origin.
  2. Set the origin domain to the bucket's regular endpoint (not the s3-website one).
  3. Origin access → Origin access control settings → create an OAC that signs requests.
  4. Save, then copy the bucket policy CloudFront generates.
  5. In S3 → bucket → Permissions → Bucket policy: paste it. It lets only cloudfront.amazonaws.com call s3:GetObject, limited by an AWS:SourceArn condition to my one distribution.
  6. Wait for the distribution to show Deployed, then reload the site.

Lesson: a working redirect says nothing about the origin.

Problem 2

www.appcomplish.click showed "not secure"
Trying to: make www.appcomplish.click open the site over HTTPS, the same as the bare domain.
What happened: after I created the Route 53 record for www, the browser said the connection was not secure.
Why: CloudFront only answers for names listed under the distribution's Alternate domain names, and www was not listed, so it refused the secure connection. The certificate was not the cause: it already covered www through *.appcomplish.click.

Fix
  1. Route 53 → Hosted zones → appcomplish.click → Create record: name www, type A, Alias on, route to my CloudFront distribution.
  2. CloudFront → my distribution → General → Settings → Edit → Alternate domain names → Add item: www.appcomplish.click.
  3. Save changes, wait for the distribution to show Deployed, then reload the site.
OptionWhy or why not
Public bucket behind CloudFrontHTTPS works, but visitors can skip CloudFront and read S3 directly.
Origin Access Identity (OAI)The older private-bucket method. AWS now recommends OAC, and OAI cannot read buckets encrypted with AWS Key Management Service keys.
Origin Access Control (OAC) Best fitThe bucket stays private, CloudFront signs each request, and there is no secret to store.

Tradeoffs: OAC needs the bucket's regular endpoint, not the website endpoint, and a missing file then returns 403 instead of 404 until I add a CloudFront custom error response. Source: Restricting access to an S3 origin
