Business Requirement

I'm moving into cloud engineering and need a public portfolio that recruiters and hiring managers anywhere can open on a phone or laptop. It has to show real AWS work, cost almost nothing, and not become another system I have to patch or babysit.

How would you host a portfolio website like this?

Summary
This portfolio is a static website: HTML, CSS and JavaScript files with no server-side code. I host it in an Amazon S3 bucket behind a Route 53 Domain Name System (DNS) record, so there is nothing to patch and it costs under $1 a month. Next I'm adding CloudFront and an ACM certificate for HTTPS and a private bucket. WAF would cost more than everything else combined, so I'm holding it back until the site needs it.

Figure 1 — Why static hosting fits: the site is only files, so an Amazon S3 bucket can serve it with no server to run. A dynamic app (server-side code, a database, user sessions) would instead need compute such as Amazon Elastic Compute Cloud (EC2) virtual servers or containers. OAC is Origin Access Control; ACM is AWS Certificate Manager.

How It Works

  1. The domain appcomplish.click is registered in Route 53, which holds the DNS record.
  2. The record points visitors to an S3 bucket configured for static website hosting.
  3. The S3 bucket serves the HTML, CSS and JavaScript files. Phase 2 puts CloudFront in front, adds an ACM certificate for HTTPS, and makes the bucket private.

Proof (Phase 1): the home page, About, Resume, Projects and the stylesheet all return HTTP 200 on appcomplish.click.

Key Decision
Static hosting on an Amazon S3 bucket instead of a server. A server (EC2 or a $5 Lightsail instance) adds a web server and ongoing patching, and a static site gets nothing from either.

Limits and Next Steps

  • No HTTPS from S3 alone. The website endpoint serves HTTP, so a custom domain with HTTPS needs CloudFront. The ACM certificate for CloudFront must be created in us-east-1.
  • No server-side logic. Forms, logins or APIs need other services, such as API Gateway with Lambda, or a different design.
  • At 10× the traffic CloudFront absorbs it as cache hits. What would break is dynamic content: user accounts, orders or a product catalog need an API, a database and session handling.
  • Cache invalidation costs money past the free tier, so versioned filenames (style.v2.css) beat invalidating on every deploy.
  • Do differently: I would have started with Terraform instead of the console and built CI/CD from the start. The pipeline is now built; Terraform is next.
